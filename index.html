Quick Start
First dialogue call in under a minute — x402 payment header included.
bash
# x402: the facilitator co-signs a 0.01 USDC payment
curl https://api.npc402.ai/v1/dialogue \
  -H "Authorization: Bearer $NPC402_KEY" \
  -H "X-Payment: x402 base-sepolia USDC 10000" \
  -H "Content-Type: application/json" \
  -d '{"persona":"VEX-7",
      "message":"Where do I find the vault?",
      "session_id":"ses_demo_01"}'
javascript
import { NPC402 } from "@npc402/sdk";

const npc = new NPC402({ apiKey: process.env.NPC402_KEY });

const res = await npc.dialogue({
  persona: "VEX-7",
  message: "Where do I find the vault?",
  sessionId: "ses_demo_01",   // auto x402 settle
});
console.log(res.reply, res.payment.txHash);
python
from npc402 import Client

npc = Client(api_key=os.environ["NPC402_KEY"])

res = npc.dialogue(
    persona="VEX-7",
    message="Where do I find the vault?",
    session_id="ses_demo_01",  # settles 0.01 USDC
)
print(res.reply, res.payment.tx_hash)

Documentation

Everything you need to ship autonomous, paid-per-dialogue NPCs — from authentication to settlement.

Getting Started Authentication x402 Payments Dialogue API RAG Memory Webhooks

01Getting Started

NPC-402 turns game characters into autonomous, hosted AI personas. Each dialogue call retrieves persona memory, generates a response, and settles a micro-payment — all in one request.

  • Create a persona with lore and a voice profile in NPC Profiles
  • Generate an API key in Developer Tools → API Keys
  • Install the SDK for your engine and send your first dialogue message
bash
# install the web SDK
npm install @npc402/web-sdk

# set your key (server-side only)
export NPC402_KEY=sk_live_npc402_••••••••

02Authentication

All requests use a bearer API key. Secret keys (sk_) must never ship in clients — use the server SDK or a signing proxy. Public keys (pk_) are read-only and safe for analytics dashboards.

http
POST /v1/dialogue HTTP/1.1
Host: api.npc402.ai
Authorization: Bearer sk_live_npc402_••••••••
Content-Type: application/json

03x402 Payments

Every dialogue call carries an X-Payment header. The facilitator verifies the EIP-191 signature, co-signs a 0.01 USDC transfer on Base Sepolia (Chain ID 84532), and returns the transaction hash with the response. Failed settlements auto-retry up to 3 times.

jsonpayment response
{
  "payment": {
    "scheme": "x402",
    "network": "base-sepolia",
    "asset": "USDC",
    "amount": "10000",
    "txHash": "0x4f2a…91c3",
    "status": "settled"
  }
}

04Dialogue API

Send a message to a persona within a session. Sessions preserve multi-turn memory server-side; reuse the same session_id to continue a conversation.

javascript
const res = await npc.dialogue({
  persona: "VEX-7",        // substrate id
  sessionId: "ses_8f21",   // stable per player
  message: "Where's the vault?",
  voice: true,             // stream OmniVoice audio
});

res.reply    // → "You don't break in…"
res.latency  // → 342 (ms)
res.memory   // → retrieved RAG chunks

05RAG & Memory

Each persona owns a vector-indexed corpus of lore documents. At inference time, the top chunks relevant to the player's message are retrieved and injected — personas stay consistent with your world bible without retraining. Upload lore as markdown, PDF, or JSON from the persona configuration panel.

  • Chunk size 512 tokens · 128-token overlap · re-indexed on upload
  • Persistent player memory: facts extracted from dialogue are written back per session
  • Retrieval traces appear in Dialogue Logs for every turn

06Webhooks

Subscribe to events your backend cares about. All webhooks are HMAC-SHA256 signed with your secret key — verify the X-NPC402-Signature header before trusting the payload.

jsondialogue.settled
{
  "event": "dialogue.settled",
  "session_id": "ses_8f21",
  "persona": "VEX-7",
  "turns": 6,
  "amount": "10000",
  "txHash": "0x4f2a…91c3"
}
